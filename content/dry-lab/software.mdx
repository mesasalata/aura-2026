<Section id="overview" title="Software overview" kicker="01">

Software supports analysis, documentation, and the on-farm load score. Nothing in the critical path requires a network connection at the parlour.

</Section>

<Section id="analysis" title="Analysis scripts" kicker="02">

Python notebooks process FET traces, subtract that sample's reference-electrode baseline, and export figures for the wiki. Scripts take raw current CSV and return a miR-223 load score with uncertainty.

<Section id="wiki" title="This wiki" kicker="03">

The site is a static Next.js export - fast, deployable to iGEM hosting, accessible without JavaScript for core content. MDX pages keep prose editable without touching layout code.

</Section>

<Section id="reader-app" title="On-farm flag" kicker="04">

The parlour computer already has the score. If it stays high across consecutive sessions, it marks the cow and sends a quiet alert to the farmer's phone or the parlour display. Privacy and data ownership would be farm-controlled; no cloud requirement in v1.

<Callout variant="note" title="Scope">
  The flag is a design target. The proof-of-concept FET and model work without a phone app.
</Callout>

</Section>
